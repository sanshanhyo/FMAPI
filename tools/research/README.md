# Archived message research tools

Original exploratory tools preserved when research was paused. They are not adapters, supported APIs, or part of the solution/CI. Prefer `FMAPI.MessageProbe` for its bounded, tested message diagnostic. No game data or third-party binaries are included.

- StaticProbe: PE/RTTI inspection, Iced disassembly, generated interop metadata/map inspection, and explicit read-only Windows live probes. Build with .NET 10 and `-p:IcedAssemblyPath=<absolute path to a separately obtained Iced.dll>`. Iced is an external MIT dependency; its source and license are at https://github.com/icedland/iced. The map layout was checked against BepInEx/Il2CppInterop's Common/Maps/MethodAddressToTokenMapBase.cs; no implementation was copied. Input binaries are opened as data, not loaded for execution.
- BundleProbe: exploratory UnityFS/LZ4 reader for one explicitly selected local archive. Modes: a search string, `bindings`, or `window:<hex offset>:<hex length>`. An optional third argument writes decompressed bytes. Do not commit any output. This is a resource-inspection aid, not a runtime dependency on game UI objects.

These prototypes can throw on invalid input and lack comprehensive parser tests. Live exploratory modes have fewer validation checks than MessageProbe, assume the analyzed object layouts, and print private raw data. They must not be automated against arbitrary processes or used as a production reader. No game functions are invoked. Run only with explicitly authorized local inputs and keep all output outside the repository.

The original prototypes built with zero warnings/errors. StaticProbe's final stream inspection succeeded before pausing. BundleProbe successfully inspected selected local archives earlier; this is not a malformed-input test suite. The existing MessageProbe synthetic self-test and framework tests passed in CI for commit 48331a5.

## Offline localization candidate decoder

`decode_localization.py` reads one explicitly selected `languages.fmf` archive as data and decodes one language entry with the separately available Python `zstandard` package (official project: https://github.com/indygreg/python-zstandard). It does not open the game process. It validates the observed FMF/LTC headers, archive/entry sizes, selected entry decompression length, index bounds, key ordering and UTF-8 record boundaries. Limits are 512 MiB archive, 64 MiB selected entry, 64 KiB index, 250,000 template entries, 16 requested keys, 16 variants and 8 KiB per string. Other format revisions fail closed. Unresolved offset flags remain unavailable. Header magic discovery is restricted to the first 64 bytes of an explicitly selected section.

Run `python tools/research/decode_localization.py --self-test` for synthetic malformed-input and basic decoding checks. For authorized private investigation, pass an archive path, `--template-id 0xA2A90 --template-id 0xABDAF`, and `--output <private-json-path-outside-repository>`. The default language is `chinese`; another name can be selected with `--language`. Keep all output local and outside source control. These are serialization/template candidates, not formatted messages. The decoder selects the observed 0x1 high-nibble key family only; it does not implement general native variant selection, hidden tokens, pronouns or entity parameter bindings.

On the pinned native build, this tool decoded the installed Chinese entry and both welcome templates. The title matched all loaded native segments after stripping the serialized token brackets; the body offset matched the unloaded live entry's low 32-bit stream-offset field. Each selected record consumed exactly to its next indexed boundary. This establishes an external template route for the observed build, not complete translated message formatting or a general archive compatibility contract. Real data and decompressed files are not bundled.
