## Observer boundary to implement after coordination

A platform observer supplies exact build identity and readiness from verified internal sources. It never infers readiness from an active UI page. Begin a generation only after qualification; invalidate before save replacement, current-manager changes, disconnect or shutdown. Uncertain or missing lifecycle signals make reads unavailable. Never cache native pointers in public API entities across generations.

A bounded read captures its token, verifies source/type/collection bounds, performs the read, then rechecks generation and source identity before returning data. Expiry discards the result. External rechecks do not lock game lifetime; a future in-process path needs verified game-thread scheduling. The current gate implements only this prerequisite policy, not the observer or scheduler.

Keep qualification (static candidate, historical observation, synthetic contract test) separate from runtime availability (ready, unavailable, expired). A successful synthetic test must never promote a candidate to live support. Existing boolean sourceVerified is an internal trusted caller prerequisite and must not be surfaced as a user-controlled grant or used as evidence storage.
