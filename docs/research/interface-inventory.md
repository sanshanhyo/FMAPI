# FMAPI 全接口盘点与实现状态

> 本文盘点目标接口，不启动扫描、不实现 SDK、不执行任何游戏操作。范围包括读取、写入/操作与事件。第一版按外部 mod 可能需要的领域尽量铺全，仍允许补漏，不声称穷尽引擎内部能力。没有证据的接口不勾选完成。
>
> 状态基于截至 2026-11-03 已核研究记录，尚未完成逐项源码审计。“未开始”表示未发现实现证据，不推断仓库外一定没人做过。mock SDK/Core 不计原生实现。本文共 157 个可继续细分的任务组，不是 157 个精确函数，也不代表已覆盖全部引擎接口。

## 状态规则

- 未开始：未发现实现证据，待检索已有代码后修订。
- 研究中：已有候选入口或研究记录，尚不能交付目标能力。
- 部分实现：有本项部分目标的读取/行为证据，范围明确受限。
- 已实现待验证：代码完成证据已取得，尚缺相应实机对照。
- 实机验证：具体构建/存档/状态范围内通过测试；不是跨版本保证。
- “已提交”专指代码是否已提交到远端 FMAPI 仓库，不能用 Windows 本地提交或 FA 项目代码替代。“可调用”分别说明已有 FA reader、独立研究代码与 FMAPI SDK；现有 FA reader 可调用不代表 FMAPI SDK 已接入。无源码证据的远端状态写“待核”。
- 下列每行是可分派子任务；含多个动作时，执行者必须再拆为单独验收项，不得用一个成功动作覆盖整行。

## 逐项分派与验收模板

1. 领取一个 ID；多动作拆成 `<ID>.1/.2/...`，不重写整个总表。
2. 先找回已有成果，包括本地分支 `research/alawell-message-reader` 的 `10a5724`、`d1f5177`、`99aba1d` 和旧比赛插件。无法访问明确标阻塞，不盲目重逆向。
3. 交付字段/参数/事件 schema 草案、来源路径与提交、当前能力、缺失子项、最小脱敏样例、复现步骤和测试记录。此处 schema 是盘点契约，不要求实现 SDK。
4. read 验收含类型、UID/关系、单位、日期、币种/工资周期、空值、刷新时间与 UI 对照。
5. write 规划含动作前后状态、权限、可逆/不可逆、确认点、失败恢复、幂等/重试边界与只读回证方式；当前只交规划，不执行动作。
6. event 规划含事件主体、时间、原生/轮询来源、顺序、去重、丢失、重连与快照关联；当前无证据保持未开始。
7. 只有实际证据支持时更新实现状态；另外独立更新“已提交”和“可调用”，附入口名称/命令、版本和已测试范围。
8. 当前阶段结束于完整初版目录和证据盘点，不以“全接口已完成”为终点。后续研究按任务 ID 由用户分派；P0/P1/P2 仅影响顺序。

## 执行约束与依赖

读数据工作可以按组织/世界、人员/培养、合同/招募、赛事/比赛、战术、消息/文本六组调度，但这些组不是领域上限。读写事件共用同一实体 UID、版本、时间和枚举规范；写与事件需要各自额外证据，不能从“可读”推断“可写/可订阅”。

`现有成果回收 → 环境/UID/单位基线 → 各域目标拆分与证据核验 → 读取/操作/事件分别验收 → 总表逐项更新`。

共享 live process 的重扫描必须串行且有字节/对象/耗时预算；其他模型可同时分析同一脱敏 capture、写独立脚本/测试。每人独立 worktree，不同时修改游戏状态。无本机权限者不能假装云端可访问本机游戏。禁止提交原始 dumps、存档、密钥或令牌。
